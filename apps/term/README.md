# apps/term

`neo-term`, neo's full-screen terminal app: the shared conversation in a pane that scrolls on its own, an input editor, status lines under the prompt, and the plan / changed-files / usage panels. `neo` with no arguments starts the daemon if needed and opens it in the current directory.

It is only a client. The conversation lives in the daemon, so closing the app never stops work, and the overlay, the desktop app and other terminals show the same session. It registers as the app `terminal` (a second one as `terminal-2`, …; kind app, not home, context `{cwd}`), and the agent moves into it when you start it or type in it.

```sh
task build                      # bin/neo-term (next to bin/neo)
neo                           # opens it (NEO_TERM overrides which binary)
neo ~/site                    # the same in another directory (neo-term ~/site)
neo-term --new                # a new session in this directory
neo-term --session 3fa9       # a session by id or unique prefix
```

Without flags it shows the agent's current session if that works in this directory (or the one given), else the most recently active session there, else creates one. When the session's last turn is over an hour old, the status line says `cache expired`: the next turn sends the whole conversation uncached. The daemon not running prints `daemon not running: run neo (or neo up)` and exits 1 before the screen is touched. Alternate screen, raw mode, bracketed paste and mouse capture are restored on exit and on panic. The mouse is captured for the wheel and for selecting in the chat: a drag reverses what it covers (past the pane's edge it scrolls) and letting go copies it (OSC 52); Shift-drag still selects through the terminal.

## Layout

```
 Sessions · 3        !1 ⣾1  │ ... chat (scrolls inside the pane;     │ plan
▎  Sticky header        now  │     follows the tail)                  │ files
▎  Done. The header now…    │                                        │
 ⣾ Fix the login        1m  │ ─────────────────────────────────────  │
   Looking at the v… +12 −3 │ > message the agent · / for commands   (grows to 8 lines)
                            │ site · main ↑1 · neo · model sonnet · in photo-editor
 ! Deploy               3m  │ ⏵⏵ accept edits on · ctx 35% · $0.18 · ⣾ working 12s · 2 queued     copied
   needs you · Pushing t…
```

- Line 1: the directory's name (the terminal has the whole path), git branch, the session's harness (`neo`, `claude`, `codex`; `neo` until a `/harness` setting says otherwise) with the settings chosen for it (`/model`, `/effort`, `/mode`, only what is set; the harness and the values stand out) and, when the agent is in another app, `in <app>`.
- Line 2: the approvals mode (see below; `(shift+tab to cycle)` after it while nothing else is said), the usage line (context and cost of the session's own agent; guests' usage is left out; left out while the sessions sidebar shows them in its Session block), then the turn state (a spinner and the time while a turn runs, queued inputs) or the lost connection in the danger color; short messages (errors from the daemon, "copied") on the right, cutting what is left of it when they don't both fit.
- A session nothing was said in yet shows the directory's name and branch, the latest sessions in the same repository when the sidebar is hidden, and the keys to start with. Settings chosen before the first prompt (the harness, model, effort) are in the status line, not the chat.
- The terminal panel, the bottom of the side column (under the todos, plan and files: the todos all they need, plan and files up to half; a thin rule between each), shows the commands the agent and its guests run (`execute` tool calls) the way a shell would: `$ command` highlighted, its output as it comes (escape sequences dropped, the last 400 lines of each, the last 50 commands), and `exit 1` in red or `running…` under it. It follows the newest output; while the chat is scrolled up it ends with the newest command at or above the chat's last row instead (`Terminal · where the chat is`), so going back shows that command's output. Focused (Tab) Up/Down/j/k, PgUp/PgDn and g/G scroll, G follows again, Esc gives the keys back; the wheel over it scrolls it. While it is there the side column takes two fifths of the room (40 to 100 columns) once the chat keeps 52, and the column shows for it alone when there is nothing else to show; it is there only once there is a command, and `/terminal` hides or shows it.
- The shared todo list (the session's `todos` events; the user and every agent change it, the agents with the `todos` tool) is the side column's top panel while it has items, `Todos`: the open ones with `[ ]` before each, wrapped, then the finished ones folded into a `▸ 3 done` row, which opens to show them (a green `[x]`, muted and struck through). The panel always takes all it needs; the terminal under it gives way. `/todo <text>` adds one; in the panel (Tab) Up/Down or j/k select, Space or Enter check it off or open it again (on the `done` row: open or close it), `x` or Delete removes it, `a` puts `/todo ` in the editor, Esc gives the keys back. Each goes to the daemon as `neo.todos` (no turn, no chat line), and the panel changes when the daemon's event comes back.
- The side column (plan above files, the terminal panel under them) shows only when there is something in it and the terminal is wide enough; untracked files no agent touched (a `.claude/` lying around) are not enough. Without a plan it is only as wide as its widest file row (at least 24 columns), else up to a third of the terminal. A diff opened from the files panel replaces the chat. Files and folders there, the diffs in the chat and each turn's changed files carry a file type icon (Nerd Font glyphs from `devicons`, in their own colors with true colors, else muted; `NEO_TERM_ICONS=off` drops them for terminals without such a font). The files panel is a tree (folders first; a folder holding only one folder is joined with it; Enter, Space or Left/Right fold and open folders, a folded one shows how many files and the counts of what is in it; a folder with more than five changed files right in it starts folded until you open it; in a repository, a file an agent changed that git sees no change in any more stays, as a muted `✓ a.rs (agent, committed)`, and opens the diff of the last commit that touched it). Tab or `/files` moves there; Enter on a file opens it whole over the chat, syntax-highlighted (bat's grammars through syntect and `two-face`, some 220 languages, by file name; colors for a dark or light background; only the part on screen is highlighted, on a thread, so a file of any length opens at once), with its changes marked and line numbers in a muted gutter (a removed line's from the old file; dropped when the overlay is too narrow) (`f` back to just the changes, `s` side by side). The view takes vim's keys, with a cursor: h/j/k/l, w/b/e, 0/^/$, gg/G, H/M/L, Ctrl-D/U, Ctrl-F/B, Ctrl-E/Y (and the wheel) to scroll, a count first (`5j`, `120G` goes to line 120), `}`/`{` or n/p between hunks, `/` to search (smart case) and n/N between matches, `v` and `V` to select characters and lines, `y` to copy the selection and `yy` the line (without the `+`/`-` signs). `c` comments on the line or the selection — a block above the lines, splitting the file there, that goes into the prompt as `@src/a.rs:12-14 text` (`@src/a.rs:12` for one line); `c` on a commented line edits it, and the prompt's copy follows (emptied, both go). The leader is Space or `\`. Long lines wrap under their line number, and `<leader>w` cuts them instead (the view then follows the cursor sideways); `<leader>e` opens the file in `$VISUAL` (else `$EDITOR`, else `vi`) at the cursor's line (`+N` for vi, vim, nano, emacs and the like, `file:N` for Helix, Zed and Sublime, `-g file:N` for VS Code and its kind) and term comes back when the editor exits. Each file has its lines added and removed since the last commit at the right edge (`+12 −3`; staged and unstaged together, a new file counts all its lines, binary files none); a narrow panel drops them before cutting the name.
- The sessions sidebar (left, a fifth of the terminal, 31 to 44 columns) lists every session under an accent `+ New chat` row that stays put while the list scrolls, grouped by where it works: a header per repository, its name followed by a rule to the edge (its main checkout's sessions directly under it) and, under it, a `worktree name` header per worktree (`<repo>/.worktrees/<name>`, or any linked worktree, found from its `.git` file and named by its branch). Sessions outside a repository group under their directory's name. Repositories and worktrees are ordered by their latest activity, sessions in a group too; a session another one delegated to (`parent`) is indented with `↳` under its parent when they share a group. Each session leads with its status in its own color, the most pressing one when several hold: an amber `!` and a bold amber title while it waits for you to answer a permission request or a choice (its own or one copied from a session it delegated to; `needs you ·` starts its second line), a blue spinner while it runs, a green `●` and a bold title when it finished a turn you haven't looked at; the header counts each at its right edge (`!1 ⣾2 ●1`), and a folded repository shows the most pressing one after its count. Then the title (bold accent for the one you are in, with a bar in the margin; `New Session` until it has one) and how long ago it was active, and under it, when there is any, a muted line with the last message (`2 queued ·` in front when inputs wait) and the `+added −removed` lines of its edits in green and red at the right edge, then a blank row. Sessions idle for more than a day fold into a muted `▸ N older` row at the end of their group, when there are at least two of them, unless one is the one you are in or has a status; Enter on it shows them (with a muted title and a fainter preview) and closes them again. It is fed by `list_sessions` at start and `session.changed` events, so other terminals' and apps' sessions move and update live. It needs 52 columns for the chat beside it (and yields to the plan / files column when both do not fit), else it is hidden; `/sidebar` switches it off and on. At its foot, while the list keeps a dozen rows, the shown session's details: `Session`, the directory it works in (`~` for home), its agent's context (`ctx 54%  108,312 / 200,000`), the tokens in and out and the cost so far (from the newest `usage` event of the session's own agent), then `Servers`: the daemon's service connectors (language servers, MCP servers) with a green `●` and their tool count when up, a red `○` and `disconnected` or the gateway's error when not, kept current by `connectors.changed`.
- While a subagent runs (and for 5 s after it ends) a list under the status lines shows it, like Claude Code's: `● main · claude`, then a row per subagent, `○ neo · deepseek-v4-flash  search tools: weather  1m 12s · 3.4k tokens` (a running one `○`, then `✓` or `✗`; its latest tool call or `thinking…`; elapsed time; its tokens from the usage events). A subagent working in a worktree of its own shows `⎇ fix-login` after its name; one started in the background (`delegate` with `background`, which returns at once) shows `[bg]` and keeps running when the turn ends, until it finishes or is stopped. A message to or from a subagent is its activity for a moment (`← main`, `→ main`). It is only drawn when the pane is at least 12 rows tall.
- Commands Claude Code runs in the background (`run_in_background`: the call ends at once, saying `Output is being written to: /tmp/…/<id>.output`) are listed under the subagents while they run (and for 5 s after): `⏵ background · 2 running`, then a row per command, `○ cargo build --release  Compiling neo v0.1  1m 12s` (`✓` or a red `✗ … exit 1` once it ended), the newest last, four at most. term tails the output file itself (every 250 ms, until its last line, `[exited with code N]`), so the terminal panel shows a background command's output as it comes, in place of the call's result. Down from an empty editor (past the subagents) selects one: the terminal panel then shows only that command (`Terminal · background command`), and Up/Down switch between them; Enter gives the panel the keys to scroll it, and Esc there or in the list shows all commands again. `x` stops the selected one: SIGTERM to the process group writing its file (found in `/proc`, so Linux only; never term's own group); Claude Code then ends the file with the exit code and tells the agent. A background command replayed with an older session's history that has ended, or whose file is gone, is not listed; neo's own bash and Codex don't run commands in the background.
- Items are drawn by `renderers/ratatui` (cached per item, width and options), with a blank line between them, tool calls included. Prose wraps at 100 columns however wide the pane; tables and code use the whole width. Three or more finished tool calls in a row, once something came after them, fold into one muted line, `15 tool calls · 7 fetch, 5 read, 3 search · 1 failed`, or `12 read` when they are all one tool (the failures red); Ctrl-O shows them all. Commands never fold: once one has run it is a single muted, italic line, what the agent said it was for (Claude Code's description) or else the command as far as it goes, without its output (Ctrl-O shows both). Edits (a call with a diff) never fold either: a finished one is `edit src/a.rs  +3 −1`, and the newest one shows under it what it changed, each change with 5 lines around it (a stretch left out is a `⋯` line), 40 rows at most; Ctrl-O doesn't spill the rest into the chat (it opens every edit's changes, still cut there): the whole file is the file view's. Once a turn is over (the next message started it, or nothing runs), a muted `3 files changed  +40 −12` block after its last item lists each file it changed, summed per path, with its counts. Tab moves the keys into the chat's files and replies (the edits' rows and those lists, reversed and bold across the pane, and the agent's replies, tinted with the accent; the latest one first): Up/Down or j/k, g/G move, Enter, Space or Ctrl-O opens the file whole over the chat like the files panel does (Ctrl-O on a reply expands the chat), `y` copies the reply as markdown (a file: its path), Esc or q give the keys back. Enter (or `v`) on a reply opens its markdown in the chat's place with vim's keys: `hjkl`, `w b e W B E`, `0 ^ $`, `gg G`, `H M L`, `{ }`, counts, Ctrl-D/U/F/B and Ctrl-E/Y; `v` and `V` select by chars and lines (`o` swaps the ends) and `y` copies the selection; `yy`/`Y`, `y` with a motion (`yw`, `y$`, `yj`, `ygg`…) copy without one; Esc or q close it. `NO_COLOR` turns colors off. Left out: a question the user allowed (the tool's own row follows), and thoughts (unless Ctrl-T shows them) except while the agent is thinking, as one `∴ thinking` line with a light sweeping over it in the accent color. Your own messages leave out the app they came from (another terminal included); messages from other apps keep it. Apps connecting, leaving and the agent moving between them are one muted line while nothing else is said (`terminal-2 disconnected · terminal is back · now in terminal`). A command breaks after `&&`, `||` and `;` (a pipeline stays whole unless it is wider than the pane); while it runs it takes at most four rows. Prose and calls have no bullet; a call that failed is red. A call that has started and not ended is running, and while a Claude Code command runs its description is its label. Tool results are one line (`⎿ first line  … +36 lines`) and the label of a call that has run at most two (a guest's command is its label); Ctrl-O shows them in full, except what a read read (a `read` call stays its one line: the agent's look at a file isn't worth a screen of it; an image it read still gets larger). Edits are syntax-highlighted like the files panel's diffs, and so is every code block by its language (` ```ts `, ` ```toml `, ` ```markdown `: headings, emphasis, inline code and links too; `shell`/`console` count as bash); without true colors the theme's accent, success and muted colors stand in. Commands are highlighted by the same Bash grammar: a call that runs one (its `command`, from neo, Claude Code or Codex) shows it highlighted in its header, broken after `&&`, `||`, `|` and `;` when long, under a label only when the title says more than the command; a command waiting for approval also breaks its long lines after `&&`, `||`, `|` and `;`. Paths inside the session's directory (a diff's, a tool's label, a turn's changed files) are shown relative to it.
- `/theme [dark|light|terminal]` (no name: the next one): `dark` paints the screen `#1c1d20` with the daemon's theme colors (the default; code on `#26282d`, accent `#5cbf8c`), `light` paints it white with high-contrast colors of its own (text `#0b0d10`, every color at least 7:1 on white, code on `#f0f1f3`, accent `#0a5c3c`; file icons darkened toward the text color), `terminal` keeps the terminal's background and text color. Painting happens after each frame is drawn, on every cell still on the terminal's default color (`theme.rs`). The choice is kept in `term.json` in the data directory.
- Side-by-side diffs (`/settings split-diffs`, the daemon's toggle for every app, sent as `user.settings`): how diffs are drawn, the edits in the chat and the file view alike. Off (the default), unified; on, the old lines on the left and the new on the right, a removal beside the addition that replaced it, where both get room (from 81 columns in the chat, 90 in the file view; narrower stays unified). `s` in the file view still switches.

**Sending during a turn.** What you send while the agent works waits in the daemon's queue and shows above the editor, one muted italic row each (`◷ its first line`, not the `›` of a sent message; at most three rows, then `… +2 more queued`), the first with `queued` at the right edge (`queued · ↑ edits` when some are yours), from any app. With `/settings steer` on (the default) neo takes it into the running turn after its next tool calls, and Claude Code gets it in the running turn at once (ACP steering, for an adapter that offers it); either way it moves into the chat then. With it off, it waits for the turn to end. Alt-Enter or Ctrl-Enter does that for one message whatever the setting says (`session.input` with `steer`): the turn goes on and takes it in, nothing is cancelled (Alt-Enter in any terminal; for Ctrl-Enter term asks the terminal to report it apart from Enter: kitty's keyboard protocol, and xterm's modifyOtherKeys for tmux with `extended-keys on`); a `/command` waits for a turn of its own, and so does everything behind it. Up in an empty editor takes your waiting messages back out of the queue (`session.unqueue`; other apps' stay) and puts them in the editor, one per paragraph, with their images, before anything typed meanwhile; edit and send them again. A harness that can't be steered (Codex) gets it when the turn ends. Whatever waits when a turn ends runs as one turn, one message with a paragraph each (up to a `/command`, which runs on its own; messages from different apps stay apart).

While scrolled up, new output does not move the view; a dim `↓ new output (End)` shows. Sending or a new prompt jumps back to the tail.

**Speech to text.** Holding Space in the editor records from the microphone (`pw-record`, else `parecord`, else `arecord`; 16 kHz mono WAV); the row over the editor says `● recording 0:04 · let go of space to stop`. Letting go sends the recording to the daemon (`speech.transcribe`), which has a model that hears audio write it out on your OpenRouter key (`~google/gemini-flash-latest`, `NEO_SPEECH_MODEL` picks another), and the text goes in at the cursor. A held Space is told apart by the key repeat: under kitty's keyboard protocol the terminal says it repeats and when it is let go; elsewhere (tmux included) Spaces coming faster than typing are a held one, the Spaces typed before that was clear are taken back out, and their stopping for 0.4 s is letting go. Claude Code's own voice mode is not used: its ACP adapter doesn't offer it, and it needs a Claude login.

**Images.** Ctrl-V pastes the image on the clipboard (read with `wl-paste` on Wayland, `xclip` on X11, saved as `$TMPDIR/neo-term/paste-<ms>.<ext>`, since the daemon takes images by path); a paste that comes in empty, which some terminals send when the clipboard holds only an image, does the same. Pasting or dropping image files (PNG, JPEG, GIF, WebP) pastes them instead of typing their paths, as long as the paste is nothing but paths of files that exist (quoted, with escaped spaces, `file://` URIs or `~/` are all fine). A pasted image goes into the draft at the cursor as a marker in the accent color, `[image 1]`, so the message says where it belongs, and a thumbnail of it shows above the editor with its marker under it (one row of `[image 1] cat.png` where the terminal shows no pictures, or there is no room). Backspace right after a marker deletes all of it and the image with it; Ctrl-C drops the draft and its images. Sent, the markers count from 1 in reading order and the images go along in that order (`session.input` with `images`); the chat shows each image where its marker was.

**Prompts.** Permission requests and choices (`/model`, `/resume`, "Start a subagent?") are items with buttons. The delegation question is a compact card: a header and, in the accent color, the Harness, Model, Effort and Directory, then the task cut to its first 12 lines (Ctrl-O shows all). The oldest one still pending is active and **takes the editor's place**: the question with a compact preview (a diff is cut to 10 lines; the chat keeps the whole item), the buttons with the first one reversed, and a line of keys (`enter allow once · ←/→ choose · tab add a note · esc dismiss`), with `(1 of 3)` when several wait (they come one at a time). While it is there nothing reaches the editor, so Enter can only answer the prompt: arrows move over the buttons, Enter or the digit presses one (`ui.action`), Esc dismisses the prompt (it stays pending in the chat; Ctrl-P brings it back). The draft in the editor is untouched and returns when the prompt is gone. If you typed within the last 800 ms when a prompt arrives, the editor stays and a line above it says `permission needed — waiting until you stop typing`; the prompt takes over after a pause. `copy:` buttons copy through OSC 52 (tmux needs `set -g set-clipboard on`). A choice with more than 9 options (`/model` with several providers) has a filter field under its title: type to narrow the list, digits included. Every word must occur in the option's name, id or description. Up/Down move over the matches, Enter picks one, Backspace deletes, Ctrl-U clears, and Esc clears the filter before it dismisses the prompt.

**Forms.** A `neoui` doc (`docs/neoui.md`: a model's ` ```neoui ` block or an app's template) whose nodes have keys (fields and buttons) is a form and works like a prompt: once it is complete (a doc that is still `streaming` takes no keys) and you have paused typing, it takes the editor's place, but it stays in the chat where it is drawn, with the margin bar and the focused target highlighted, and the chat scrolls to keep that target in view. Under the chat one line says what the focused target does with the keys (`Email · type · enter submits · tab next · esc input`). Only forms the user has not spoken after take the editor on their own; older ones, and docs that only have tabs, accordions, carousels or follow-up suggestions, are reached with Ctrl-P / Ctrl-N (while one is in the chat and nothing has the keys, the status line says `ctrl-p use the buttons above`), and a tool result with focus is drawn in full instead of as one line. Tab / Shift-Tab (and Up / Down, also in a one-line field; in a text area they move in the text first) go through the targets in drawing order and wrap around; hidden targets (a tab that is not selected, a closed accordion item) are not on the way. Typing, Backspace, Delete, Left / Right, Home / End, Ctrl-A / E / U / K / W edit the focused field in a local buffer with its own cursor; the daemon's value for that field is ignored while it has focus, and shows again when focus moves away. Enter in a text area is a newline; in any other field it presses the form's first button (the first one of the doc outside a form); on a button it presses it; on a tab strip it selects the next tab, on an accordion item it opens or closes it. Space toggles a checkbox or switch, or the item under the cursor of a checkbox / switch group (Up / Down move the cursor between its items, and on from its first or last item to the neighbouring field) (and presses a button, opens a closed select, toggles an accordion item). Left / Right pick the previous / next option of a radio group, option cards or select, move a slider by its step (Home / End: its ends), switch tabs, scroll a carousel (Home / End: its ends), close / open an accordion item, and move between buttons. Enter or Space on a select opens its list (Up / Down, Enter chooses, Esc closes it); Esc otherwise gives the editor back (the form stays pending; Ctrl-P brings it back). Pressing a button does not dismiss the form, so the answer (field errors) can be fixed in place.

Values go to the daemon as `ui.action {session, ref, action: "neoui.input", args: {doc, key, value}}`: text 150 ms after the last key (a date only once it is a valid `YYYY-MM-DD`, or empty), checkboxes, switches, choices and sliders at once. A press sends what is still waiting first, then `neoui.press {doc, key}`. A button with a `url` opens in the browser (`xdg-open`; `http`, `https` and `mailto` only, else the link is shown in the status line; no `xdg-open` says so), one with `copy` copies through OSC 52. A value chosen here shows at once and stays until the daemon echoes it or the focus leaves.

**Notes.** Tab on a permission request or choice opens a one-line input under the buttons (`note › `): type what the agent should hear ("use tabs instead"), Enter answers with the focused button plus the note (`neo.permit` / `neo.choose` with `note` in the args), Esc goes back to the buttons. The answered card shows `Allow · “use tabs instead”`.

**Secrets.** A command that needs an API key or a pasted login code (`/login`) asks for it in a masked field that takes the editor's place: the title, the typed characters as `•`, and `enter submit · esc cancel`. Enter sends the value to the daemon, Esc (or Ctrl-C) sends none. Every other key is text or nothing, and a paste goes into the field. The value is kept only in the field and wiped when it is sent. It is not in the editor, the input history, the chat or the session log, and a second question replaces the first (which is answered as cancelled). The question dies with the connection or a switch of session.

**Subagents.** With focus on the list (Ctrl-X, or Down from an empty editor that is not walking through history; the selected row is reversed): Up/Down or j/k select (Up from the top row gives the keys back), Enter opens that subagent's **transcript** over the chat, `x` stops it (the delegate call returns "stopped: cancelled" and the turn goes on; a background subagent reports that as a message that does not start a turn), Esc, q, h or Left give the keys back. The transcript is the daemon's per-agent view (`view.subscribe` with `agent`): the task, the agent's thoughts, tool calls and replies, drawn like the chat; Up/Down, PgUp/PgDn, Space, u/d, g/G (or the wheel) scroll, Ctrl-O shows full tool results, Ctrl-T thoughts, Esc or q go back. Enter on a subagent that works as a session of its own (delegated with `cwd` or `worktree`) switches to that session instead; the app follows such a session's events to fill in its row. Messages between agents (`send_message`, a background subagent's final reply) are compact tool rows in the chat, `message: main → claude d_1a2b3c4d` or `reply: claude d_1a2b3c4d → main`, folded like any tool result (Ctrl-O shows the text); in a transcript what was written to the subagent is input like its task (`from main`) and what it sent is a row. The turn an idle agent starts for a message is not drawn as something you said. Esc or Ctrl-C on the session's turn also stops its background subagents. Subagents are the ones the agent delegated to; a direct `/claude task` turn stays inline in the chat.

**Sessions sidebar.** With focus (Ctrl-G or Tab; the selected row is reversed): Up/Down or j/k move over `+ New chat` and the sessions (the group headers are skipped), `[` / `]` or Ctrl-Up / Ctrl-Down jump to the first session of the previous / next group, PgUp/PgDn, g/G jump to the ends, Enter shows that session (the same switch as the `/sessions` picker: the agent moves here too), Enter on `+ New chat` or `n` anywhere starts a new session in this directory and shows it (the picker's `New` entry; the session you were in stays), Esc, q, h or Left give the keys back to the editor.

**Commands.** `/` at the start of the input opens a menu (Up/Down, Tab completes, Enter runs). Sent to the daemon like any input: `/clear`, `/new`, `/cd [dir]` (move the session to another directory; term's files, git and paths follow it), `/model`, `/effort`, `/mode`, `/resume`, `/claude <task>`, `/codex <task>`, `/harness [neo|claude|codex]` (switch this session's agent), `/approvals [ask|review|edits|auto]`, `/safesearch [strict|moderate|off]`, `/settings [toggle [on|off]]` (a card of the user's toggles, such as "Show, don't tell."; picking one flips it), `/login`, `/logout`, `/accounts`, `/plugin …` (marketplaces and plugins). After these the menu lists the commands of the harness the session runs on: Claude Code's and Codex's own (`/review main` goes to them as text), neo's plugin commands; ours win a name clash. Local: `/sessions`, `/sidebar`, `/expand`, `/thoughts`, `/github`, `/help`, `/theme`, `/quit`.

**`/clear`** clears the agent's context and stays in the session: the chat, todos and settings stay, the agent's next turn starts a new conversation, and the context meter drops to 0%. **`/new`** makes the daemon switch to a fresh session in the same directory; the app follows it (the next `agent.focus` names it) and starts over with an empty chat and panels.

**Approvals.** `ask` (default) asks before file edits, commands, starting a guest and guests' requests; `review` writes each edit right away and then asks Keep / Revert for that edit (a card with its diff; the agent is told when you revert); `edits` writes the agent's edits right away and asks for the rest, and after the turn a card offers Keep / Revert all / Revert <file>; `auto` asks for nothing. Reads are allowed in every mode, except sensitive files (`.env`, keys, credentials) and commands that mention them, which ask in every mode. Shift-Tab sends `/approvals review|edits|auto|ask` (the next mode); the mode comes back as a `setting_changed {harness: "daemon", option: "approvals"}` event, so every pane agrees, and the status line names it (`? ask before acting`, `⏵ review each edit`, `⏵⏵ accept edits on`, `⏵⏵ auto mode on`). Changing it is not shown in the chat.

A permission request that would change a file (or, in review mode, did) shows the diff above its buttons (additions green, removals red). Up to 12 lines are shown, then `… N more lines`; Ctrl-O shows the whole diff. The buttons stay at the end of the item, where the view jumps to when the request arrives.

**Diff view.** Enter on a file in the files panel opens its `git diff HEAD` over the chat, side by side (old left, new right) from 90 columns and unified below that. It takes every key while open: Up/Down or j/k, PgUp/PgDn, g/G, Ctrl-U/Ctrl-D scroll; `n` / `p` jump to the next / previous hunk; Left/Right or `h` / `l` scroll sideways 8 cells and `0` goes back to the left edge (long lines are cut, the marked change stays in place); `s` switches split and unified; `f` shows the whole file as context and back (it no longer pages); Esc or `q` close it.

**GitHub.** Ctrl-R or `/github` opens a full-screen view over the chat for the repository `gh` finds in the session's directory (it needs the [GitHub CLI](https://cli.github.com), logged in with `gh auth login`; a missing `gh`, a directory that is not a GitHub repository and a missing login are said so on the screen). It only reads: every command is checked against a read-only allowlist (listing and viewing issues and pull requests, a pull request's diff, one `gh api repos/…` GET) before it runs, so the app cannot write to GitHub. Everything loads on background threads with a `loading…` line; lists and details are cached until the session's directory changes (`r` reloads).

- _List_: tabs Issues / Pull requests (Tab or 1 / 2), each row `#number`, state (open green, closed red, merged accent, draft muted), title, labels, author, comment count and the time since the last update (`3h`, `2d`, `3w`). Up/Down or j/k, PgUp/PgDn, g/G and the mouse wheel move; Enter opens; `/` types a search (GitHub's search syntax, e.g. `label:bug author:alice`; Enter applies, Esc cancels); `o` switches open / all states; `r` reloads; Esc or `q` close. Columns drop from the right as the terminal narrows (labels, author, comments).
- _Detail_: title, state, author, labels, the description (markdown read in the terminal: headings, lists, quotes, code, bold / italic / inline code, links; HTML comments from templates are dropped), the comments in order, and for a pull request also the branches and size, the review decision, reviews, comments on the diff, the checks (failing and pending ones named) and the changed files. Scrolls like the diff view (keys and wheel). `d` shows a pull request's diff in the diff view above (Esc comes back). Esc goes back to the list, `q` closes.
- _To the model_: `a` (Enter in a detail) puts a `<github-issue repo="o/r" number="12" url="…" state="open">…</github-issue>` block (`<github-pr …>` for a pull request) into the editor after what is already typed and closes the view, so you can add instructions; `s` sends it at once as a user message after a line like `Here is issue #12 from GitHub.`. The block holds the title, facts, description and conversation (comments, reviews, comments on the diff), cut to about 12000 characters: the description and each comment are shortened, the oldest comments dropped first with a note. From the list both keys fetch the detail first if it is not cached (the footer says `fetching #12…`).

**Images.** An `image` component in the conversation (what you attach to a message, a picture the agent read, any component an app shows, an `Image` or `ImageGallery` in a neoui doc) is drawn as a picture in the chat, not as `[image …]`: up to 12 rows tall (30 with Ctrl-O), the aspect ratio kept, never wider than the chat or larger than the file, with a muted `name · 1024×768` caption under it. The file is found from the component's `src`: a path (relative ones to the session's directory), a `file://` URL, an `asset://` handle, which the daemon resolves (`get_asset`), or an `http(s)://` URL, which the daemon downloads into its asset store (`fetch_asset`: public hosts only, png / jpeg / gif / webp up to 20 MB, each URL once). `data:` sources are not loaded. Until the size is known the item says `[image name] loading image…`, and a file that is missing or not a png / jpeg / gif / webp says why in the same place. Loading, decoding and encoding run on two background threads, only for pictures in view; scrolling cuts a picture at the pane's edges (every row that shows is drawn), and the encoded pictures are kept by source and size (the 32 most recently drawn). What the terminal can draw is asked at start, after raw mode is on: kitty graphics, sixel and iTerm2 where they work, else half blocks (colored `▀` cells; no answer within a second counts as half blocks). `NEO_TERM_IMAGES` overrides: `kitty`, `sixel`, `iterm2`, `halfblocks`, or `off` for the old `[image …]` text. Inside tmux (3.3+), passthrough is turned on for term's pane on its own, but kitty's answer to the query does not come back through tmux: when the query finds nothing, term asks tmux which terminal its client runs in and uses kitty graphics for kitty and Ghostty (`NEO_TERM_IMAGES` still overrides). Sixel and iTerm2 inside tmux need the terminal to answer. Kitty pictures are drawn as unicode placeholder cells, so they scroll, clip and clear with the text. Subagent transcripts still show the text placeholder.

**Sessions.** `/sessions` lists sessions (title, directory, age, state); type to filter, Enter switches (and moves the agent to the new one), the first row starts a new session here. Input history is kept per session in memory and in `<data dir>/term-history/<session>.jsonl`.

## How it is built

- `app.rs`: `App` is the whole state; `handle_key`, `handle_event` (the SDK's events), `handle_msg` and `tick` return `Effect`s (send input, press a button, cancel, switch session, copy, open a link, quit) and `draw` paints a frame. No terminal or network in it.
- `driver.rs`: picks the session at start, runs effects on a worker thread (SDK requests block up to 10 s) and pumps events into the app.
- `runtime.rs`: terminal setup and restore, the loop (poll keys 50 ms, drain events, tick, redraw only when something changed).
- `chat.rs` (view items, cached lines, scrolling, where the images sit and the focused neoui target), `forms.rs` (the keys and visual state of neoui docs, and the values waiting to be sent), `images.rs` (terminal detection, the probe and encode threads, drawing pictures), `editor.rs`, `history.rs`, `secret.rs` (the masked field), `menu.rs` (commands, switcher), `status.rs`, `sessions.rs` (the sessions sidebar, grouped by repository and worktree), `agents.rs` (the subagents list and a transcript), `widgets/` (side panels), `github/` (the GitHub view: `gh.rs` the read-only runner behind a trait, `model.rs` the JSON, `md.rs` / `doc.rs` / `view.rs` drawing, `format.rs` the block for the model).

## Tests

`cargo test -p neo-term`: unit tests for editing, history, the slash menu, scrolling and follow, prompt buttons, neoui forms (focus, typing, debounce, select, buttons, tabs, scrolling to the focus), Esc / Ctrl-C, status lines, session choice, the GitHub view (recorded `gh` JSON through a fake runner, no network), the subagents list, its keys and the transcript, the sidebar's groups and keys, image slots, clipping and the cache, pictures drawn through every protocol into the buffer (png files made on the fly), and screen snapshots at 100x30, 60x20 and others (`tests/snapshots/`, rewritten with `UPDATE_SNAPSHOTS=1`), all on ratatui's `TestBackend`. `tests/daemon.rs` starts the real daemon (echo agent, temp socket and data dir; skipped without bun), connects the app, chats, toggles approvals, `/clear`s, `/new`s, and runs two terminals side by side. Nothing opens a terminal.
