# apps/term

`suite-term`, the suite's full-screen terminal app: the shared conversation in a pane that scrolls on its own, an input editor, status lines under the prompt, and the plan / changed-files / usage panels. `suite` with no arguments starts the daemon if needed and opens it in the current directory.

It is only a client. The conversation lives in the daemon, so closing the app never stops work, and the overlay, Pad, the browser, the photo editor and other terminals show the same session. It registers as the app `terminal` (a second one as `terminal-2`, …; kind app, not home, context `{cwd}`), and the agent moves into it when you start it or type in it.

```sh
make build                      # bin/suite-term (next to bin/suite)
suite                           # opens it (SUITE_TERM overrides which binary)
suite-term --new                # a new session in this directory
suite-term --session 3fa9       # a session by id or unique prefix
```

Without flags it shows the agent's current session if that works in this directory, else the most recently active session here, else creates one. The daemon not running prints `daemon not running: run suite (or suite up)` and exits 1 before the screen is touched. Alternate screen, raw mode and bracketed paste are restored on exit and on panic. There is no mouse capture, so tmux (or the terminal) selects text as usual.

## Layout

```
 Sessions · 3               │ ... chat (scrolls inside the pane;     │ plan
▎  Sticky header            │     follows the tail)                  │ files
▎  Done. The header now…    │                                        │
 ◐ Fix the login  +12 −3    │ ─────────────────────────────────────  │
   Looking at the valid…    │ > message the agent · / for commands   (grows to 8 lines)
                            │ ~/site · main ↑1 · neo · model sonnet · in photo-editor
                            │ ctx 35% · $0.18 · ◐ working 12s · 2 queued · disconnected — reconnecting
                            │ ⏵⏵ accept edits on (shift+tab to cycle)       press ctrl-c again to quit
```

- Line 1: the directory, git branch, the session's harness (`neo`, `claude`, `codex`; `neo` until a `/harness` setting says otherwise) with the settings chosen for it (`/model`, `/effort`, `/mode`, only what is set) and, when the agent is in another app, `in <app>`.
- Line 2: the usage line (context and cost of the session's own agent; guests' usage is left out), then the turn state (a spinner and the time while a turn runs, queued inputs) or the lost connection in the danger color.
- Line 3: the approvals mode (see below), and short messages (errors from the daemon, "copied").
- The terminal panel, right of the chat, shows the commands the agent and its guests run (`execute` tool calls) the way a shell would: `$ command` highlighted, its output as it comes (escape sequences dropped, the last 400 lines of each, the last 50 commands), and `exit 1` in red or `running…` under it. It follows the newest output; focused (Tab) Up/Down/j/k, PgUp/PgDn and g/G scroll, G follows again, Esc gives the keys back; the wheel over it scrolls it. It takes two fifths of the room (40 to 100 columns) once the chat keeps 52, and only once there is a command; `/terminal` hides or shows it.
- The side column (plan above files) shows only when there is something in it and the terminal is wide enough. A diff opened from the files panel replaces the chat. The files panel is a tree (folders first; a folder holding only one folder is joined with it; Enter, Space or Left/Right fold and open folders, a folded one shows the counts of what is in it). Tab or `/files` moves there; Enter on a file opens it whole over the chat, syntax-highlighted (syntect's grammars, by file name; colors for a dark or light background), with its changes marked and line numbers in a muted gutter (a removed line's from the old file; dropped when the overlay is too narrow) (`f` back to just the changes, `s` side by side). Each file has its lines added and removed since the last commit at the right edge (`+12 −3`; staged and unstaged together, a new file counts all its lines, binary files none); a narrow panel drops them before cutting the name.
- The sessions sidebar (left, 31 columns) lists every session, grouped by where it works: a muted header per repository (its main checkout's sessions directly under it) and, under it, a `⎇ name` header per worktree (`<repo>/.worktrees/<name>`, or any linked worktree, found from its `.git` file and named by its branch). Sessions outside a repository group under their directory's name. Repositories and worktrees are ordered by their latest activity, sessions in a group too; a session another one delegated to (`parent`) is indented with `↳` under its parent when they share a group. Each session shows a spinner while it runs, the title (bold accent for the one you are in, with a bar in the margin), `+added −removed` lines of its edits in green and red, and under the title a muted line with the last message (`2 queued ·` in front when inputs wait). It is fed by `list_sessions` at start and `session.changed` events, so other terminals' and apps' sessions move and update live. It needs 52 columns for the chat beside it (and yields to the plan / files column when both do not fit), else it is hidden; `/sidebar` switches it off and on.
- While a subagent runs (and for 5 s after it ends) a list under the status lines shows it, like Claude Code's: `● main · claude`, then a row per subagent, `○ neo · deepseek-v4-flash  search tools: weather  1m 12s · 3.4k tokens` (a running one `○`, then `✓` or `✗`; its latest tool call or `thinking…`; elapsed time; its tokens from the usage events). A subagent working in a worktree of its own shows `⎇ fix-login` after its name; one started in the background (`delegate` with `background`, which returns at once) shows `[bg]` and keeps running when the turn ends, until it finishes or is stopped. A message to or from a subagent is its activity for a moment (`← main`, `→ main`). It is only drawn when the pane is at least 12 rows tall.
- Items are drawn by `renderers/ratatui` (cached per item, width and options), with a blank line between them, except between tool rows, which follow each other. Prose wraps at 100 columns however wide the pane; tables and code use the whole width. Three or more finished tool calls in a row, once something came after them, fold into one muted line, `● 15 tool calls · 7 fetch, 5 bash, 3 search · 1 failed`; Ctrl-O shows them all. `NO_COLOR` turns colors off. Left out: a question the user allowed (the tool's own row follows), and thoughts (unless Ctrl-T shows them) except while the agent is thinking, as one `∴ thinking` line with a light sweeping over it in the accent color. Tool results are one line (`⎿ first line  … +36 lines`); Ctrl-O shows them in full. Commands are highlighted: neo's `bash: …` rows, code blocks marked `bash`/`sh`/`shell`/`zsh`/`console`, and a command waiting for approval, whose long lines also break after `&&`, `||`, `|` and `;`.
- `/theme [dark|light|terminal]` (no name: the next one): `dark` paints the screen `#1c1d20` with the daemon's theme colors (the default; code on `#26282d`, accent `#5cbf8c`), `light` paints it `#f4ebd9` with colors of its own (code on `#e8ddc7`, accent black), `terminal` keeps the terminal's background and text color. Painting happens after each frame is drawn, on every cell still on the terminal's default color (`theme.rs`). The choice is kept in `term.json` in the data directory.

## Keys

| Key                                          | What                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Enter                                        | send (trimmed, non-empty)                                                                           |
| Alt-Enter, Ctrl-J                            | new line (pasting several lines keeps them in the editor)                                           |
| Up / Down                                    | move between lines; on the first / last line through this session's input history                   |
| Ctrl-A / Ctrl-E, Alt-B / Alt-F, Left / Right | line start / end, words, characters                                                                 |
| Ctrl-W, Ctrl-U, Ctrl-K, Alt-D                | delete word back, to line start, to line end, word forward                                          |
| PgUp / PgDn                                  | scroll the chat a page                                                                              |
| Mouse wheel, Shift-Up / Shift-Down           | scroll the chat 3 lines / 1 line (the mouse is captured: select text with Shift-drag)               |
| Home / End                                   | top / bottom of the chat when the editor is empty (Ctrl-Home / Ctrl-End always)                     |
| Ctrl-U / Ctrl-D                              | half page up / down when the editor is empty (Ctrl-D quits when the chat is at the tail)            |
| Ctrl-O                                       | expand / collapse tool results (`/expand`)                                                          |
| Ctrl-T                                       | show / hide thoughts (`/thoughts`)                                                                  |
| Esc                                          | close the menu; else dismiss the prompt (the editor comes back); else cancel the running turn       |
| Ctrl-C                                       | clear the editor; on an empty editor press twice within 1.5 s to quit                               |
| Shift-Tab                                    | approvals: ask → review → accept edits → auto → ask (`/approvals <next>`)                           |
| Tab                                          | complete the slash command; a note for the agent on a prompt; else editor → Sessions → Plan → Files |
| Ctrl-G                                       | focus the sessions sidebar (shows it if switched off); again to leave                               |
| Ctrl-S                                       | session switcher (`/sessions`)                                                                      |
| Ctrl-X, Down (empty editor)                  | focus the subagents list under the status lines (when one is shown)                                 |
| Ctrl-R                                       | GitHub issues and pull requests (`/github`)                                                         |
| 1-9, arrows, Enter                           | answer the active prompt (it has taken the editor's place)                                          |
| Ctrl-P / Ctrl-N                              | pick an older prompt or form / back (else history)                                                  |
| Tab, Shift-Tab, Up / Down (in a form)        | next / previous field, button, tab strip or accordion item                                          |
| Space, Left / Right, Enter (in a form)       | toggle a checkbox or switch; pick, adjust or switch tab; open, choose, press                        |
| ? (empty editor), `/help`                    | key list                                                                                            |
| Ctrl-L                                       | repaint                                                                                             |

While scrolled up, new output does not move the view; a dim `↓ new output (End)` shows. Sending or a new prompt jumps back to the tail.

**Prompts.** Permission requests and choices (`/model`, `/resume`, "Start a subagent?") are items with buttons. The delegation question is a compact card: a header and, in the accent color, the Harness, Model, Effort and Directory, then the task cut to its first 12 lines (Ctrl-O shows all). The oldest one still pending is active and **takes the editor's place**: the question with a compact preview (a diff is cut to 10 lines; the chat keeps the whole item), the buttons with the first one reversed, and a line of keys (`enter allow once · ←/→ choose · tab add a note · esc dismiss`), with `(1 of 3)` when several wait (they come one at a time). While it is there nothing reaches the editor, so Enter can only answer the prompt: arrows move over the buttons, Enter or the digit presses one (`ui.action`), Esc dismisses the prompt (it stays pending in the chat; Ctrl-P brings it back). The draft in the editor is untouched and returns when the prompt is gone. If you typed within the last 800 ms when a prompt arrives, the editor stays and a line above it says `permission needed — waiting until you stop typing`; the prompt takes over after a pause. `copy:` buttons copy through OSC 52 (tmux needs `set -g set-clipboard on`). A choice with more than 9 options (`/model` with several providers) has a filter field under its title: type to narrow the list, digits included. Every word must occur in the option's name, id or description. Up/Down move over the matches, Enter picks one, Backspace deletes, Ctrl-U clears, and Esc clears the filter before it dismisses the prompt.

**Forms.** An `openui` doc (`docs/openui.md`: a model's ` ```openui ` block or an app's template) whose nodes have keys (fields and buttons) is a form and works like a prompt: once it is complete (a doc that is still `streaming` takes no keys) and you have paused typing, it takes the editor's place, but it stays in the chat where it is drawn, with the margin bar and the focused target highlighted, and the chat scrolls to keep that target in view. Under the chat one line says what the focused target does with the keys (`Email · type · enter submits · tab next · esc input`). Only forms the user has not spoken after take the editor on their own; older ones, and docs that only have tabs, accordions or follow-up suggestions, are reached with Ctrl-P / Ctrl-N, and a tool result with focus is drawn in full instead of as one line. Tab / Shift-Tab (and Up / Down, also in a one-line field; in a text area they move in the text first) go through the targets in drawing order and wrap around; hidden targets (a tab that is not selected, a closed accordion item) are not on the way. Typing, Backspace, Delete, Left / Right, Home / End, Ctrl-A / E / U / K / W edit the focused field in a local buffer with its own cursor; the daemon's value for that field is ignored while it has focus, and shows again when focus moves away. Enter in a text area is a newline; in any other field it presses the form's first button (the first one of the doc outside a form); on a button it presses it; on a tab strip it selects the next tab, on an accordion item it opens or closes it. Space toggles a checkbox or switch, or the item under the cursor of a checkbox / switch group (Up / Down move the cursor between its items, and on from its first or last item to the neighbouring field) (and presses a button, opens a closed select, toggles an accordion item). Left / Right pick the previous / next option of a radio group, option cards or select, move a slider by its step (Home / End: its ends), switch tabs, close / open an accordion item, and move between buttons. Enter or Space on a select opens its list (Up / Down, Enter chooses, Esc closes it); Esc otherwise gives the editor back (the form stays pending; Ctrl-P brings it back). Pressing a button does not dismiss the form, so the answer (field errors) can be fixed in place.

Values go to the daemon as `ui.action {session, ref, action: "openui.input", args: {doc, key, value}}`: text 150 ms after the last key (a date only once it is a valid `YYYY-MM-DD`, or empty), checkboxes, switches, choices and sliders at once. A press sends what is still waiting first, then `openui.press {doc, key}`. A button with a `url` opens in the browser (`xdg-open`; `http`, `https` and `mailto` only, else the link is shown in the status line; no `xdg-open` says so), one with `copy` copies through OSC 52. A value chosen here shows at once and stays until the daemon echoes it or the focus leaves.

**Notes.** Tab on a permission request or choice opens a one-line input under the buttons (`note › `): type what the agent should hear ("use tabs instead"), Enter answers with the focused button plus the note (`suite.permit` / `suite.choose` with `note` in the args), Esc goes back to the buttons. The answered card shows `Allow · “use tabs instead”`.

**Secrets.** A command that needs an API key or a pasted login code (`/login`) asks for it in a masked field that takes the editor's place: the title, the typed characters as `•`, and `enter submit · esc cancel`. Enter sends the value to the daemon, Esc (or Ctrl-C) sends none. Every other key is text or nothing, and a paste goes into the field. The value is kept only in the field and wiped when it is sent. It is not in the editor, the input history, the chat or the session log, and a second question replaces the first (which is answered as cancelled). The question dies with the connection or a switch of session.

**Subagents.** With focus on the list (Ctrl-X, or Down from an empty editor that is not walking through history; the selected row is reversed): Up/Down or j/k select (Up from the top row gives the keys back), Enter opens that subagent's **transcript** over the chat, `x` stops it (the delegate call returns "stopped: cancelled" and the turn goes on; a background subagent reports that as a message that does not start a turn), Esc, q, h or Left give the keys back. The transcript is the daemon's per-agent view (`view.subscribe` with `agent`): the task, the agent's thoughts, tool calls and replies, drawn like the chat; Up/Down, PgUp/PgDn, Space, u/d, g/G (or the wheel) scroll, Ctrl-O shows full tool results, Ctrl-T thoughts, Esc or q go back. Enter on a subagent that works as a session of its own (delegated with `cwd` or `worktree`) switches to that session instead; the app follows such a session's events to fill in its row. Messages between agents (`send_message`, a background subagent's final reply) are compact tool rows in the chat, `message: main → claude d_1a2b3c4d` or `reply: claude d_1a2b3c4d → main`, folded like any tool result (Ctrl-O shows the text); in a transcript what was written to the subagent is input like its task (`from main`) and what it sent is a row. The turn an idle agent starts for a message is not drawn as something you said. Esc or Ctrl-C on the session's turn also stops its background subagents. Subagents are the ones the agent delegated to; a direct `/claude task` turn stays inline in the chat.

**Sessions sidebar.** With focus (Ctrl-G or Tab; the selected row is reversed): Up/Down or j/k move over the sessions (the group headers are skipped), `[` / `]` or Ctrl-Up / Ctrl-Down jump to the first session of the previous / next group, PgUp/PgDn, g/G jump to the ends, Enter shows that session (the same switch as the Ctrl-S picker: the agent moves here too), Esc, q, h or Left give the keys back to the editor.

**Commands.** `/` at the start of the input opens a menu (Up/Down, Tab completes, Enter runs). Sent to the daemon like any input: `/clear`, `/model`, `/effort`, `/mode`, `/resume`, `/claude <task>`, `/codex <task>`, `/harness [neo|claude|codex]` (switch this session's agent), `/approvals [ask|review|edits|auto]`, `/safesearch [strict|moderate|off]`, `/login`, `/logout`, `/accounts`. Local: `/sessions`, `/sidebar`, `/expand`, `/thoughts`, `/github`, `/help`, `/theme`, `/quit`.

**`/clear`** makes the daemon switch to a fresh session in the same directory; the app follows it (the next `agent.focus` names it) and starts over with an empty chat and panels.

**Approvals.** `ask` (default) asks before file edits, commands, starting a guest and guests' requests; `review` writes each edit right away and then asks Keep / Revert for that edit (a card with its diff; the agent is told when you revert); `edits` writes the agent's edits right away and asks for the rest, and after the turn a card offers Keep / Revert all / Revert <file>; `auto` asks for nothing. Reads are allowed in every mode, except sensitive files (`.env`, keys, credentials) and commands that mention them, which ask in every mode. Shift-Tab sends `/approvals review|edits|auto|ask` (the next mode); the mode comes back as a `setting_changed {harness: "suite", option: "approvals"}` event, so every pane agrees, and the status line names it (`? ask before acting`, `⏵ review each edit`, `⏵⏵ accept edits on`, `⏵⏵ auto mode on`). Changing it is not shown in the chat.

A permission request that would change a file (or, in review mode, did) shows the diff above its buttons (additions green, removals red). Up to 12 lines are shown, then `… N more lines`; Ctrl-O shows the whole diff. The buttons stay at the end of the item, where the view jumps to when the request arrives.

**Diff view.** Enter on a file in the files panel opens its `git diff HEAD` over the chat, side by side (old left, new right) from 90 columns and unified below that. It takes every key while open: Up/Down or j/k, PgUp/PgDn, g/G, Ctrl-U/Ctrl-D scroll; `n` / `p` jump to the next / previous hunk; Left/Right or `h` / `l` scroll sideways 8 cells and `0` goes back to the left edge (long lines are cut, the marked change stays in place); `s` switches split and unified; `f` shows the whole file as context and back (it no longer pages); Esc or `q` close it.

**GitHub.** Ctrl-R or `/github` opens a full-screen view over the chat for the repository `gh` finds in the session's directory (it needs the [GitHub CLI](https://cli.github.com), logged in with `gh auth login`; a missing `gh`, a directory that is not a GitHub repository and a missing login are said so on the screen). It only reads: every command is checked against a read-only allowlist (listing and viewing issues and pull requests, a pull request's diff, one `gh api repos/…` GET) before it runs, so the app cannot write to GitHub. Everything loads on background threads with a `loading…` line; lists and details are cached until the session's directory changes (`r` reloads).

- _List_: tabs Issues / Pull requests (Tab or 1 / 2), each row `#number`, state (open green, closed red, merged accent, draft muted), title, labels, author, comment count and the time since the last update (`3h`, `2d`, `3w`). Up/Down or j/k, PgUp/PgDn, g/G and the mouse wheel move; Enter opens; `/` types a search (GitHub's search syntax, e.g. `label:bug author:alice`; Enter applies, Esc cancels); `o` switches open / all states; `r` reloads; Esc or `q` close. Columns drop from the right as the terminal narrows (labels, author, comments).
- _Detail_: title, state, author, labels, the description (markdown read in the terminal: headings, lists, quotes, code, bold / italic / inline code, links; HTML comments from templates are dropped), the comments in order, and for a pull request also the branches and size, the review decision, reviews, comments on the diff, the checks (failing and pending ones named) and the changed files. Scrolls like the diff view (keys and wheel). `d` shows a pull request's diff in the diff view above (Esc comes back). Esc goes back to the list, `q` closes.
- _To the model_: `a` (Enter in a detail) puts a `<github-issue repo="o/r" number="12" url="…" state="open">…</github-issue>` block (`<github-pr …>` for a pull request) into the editor after what is already typed and closes the view, so you can add instructions; `s` sends it at once as a user message after a line like `Here is issue #12 from GitHub.`. The block holds the title, facts, description and conversation (comments, reviews, comments on the diff), cut to about 12000 characters: the description and each comment are shortened, the oldest comments dropped first with a note. From the list both keys fetch the detail first if it is not cached (the footer says `fetching #12…`).

**Images.** An `image` component in the conversation (what you attach to a message, a picture the agent read, any component an app shows) is drawn as a picture in the chat, not as `[image …]`: up to 12 rows tall (30 with Ctrl-O), the aspect ratio kept, never wider than the chat or larger than the file, with a muted `name · 1024×768` caption under it. The file is found from the component's `src`: a path (relative ones to the session's directory), a `file://` URL, or an `asset://` handle, which the daemon resolves (`get_asset`). `data:` and `http(s)` sources are not loaded. Until the size is known the item says `[image name] loading image…`, and a file that is missing or not a png / jpeg / gif / webp says why in the same place. Loading, decoding and encoding run on two background threads, only for pictures in view; scrolling cuts a picture at the pane's edges (every row that shows is drawn), and the encoded pictures are kept by source and size (the 32 most recently drawn). What the terminal can draw is asked at start, after raw mode is on: kitty graphics, sixel and iTerm2 where they work, else half blocks (colored `▀` cells; no answer within a second counts as half blocks). `SUITE_TERM_IMAGES` overrides: `kitty`, `sixel`, `iterm2`, `halfblocks`, or `off` for the old `[image …]` text. Inside tmux, kitty and sixel need passthrough: `set -g allow-passthrough on` (tmux 3.3+); without it the terminal does not answer the query and you get half blocks. Kitty pictures are drawn as unicode placeholder cells, so they scroll, clip and clear with the text. Subagent transcripts still show the text placeholder.

**Sessions.** Ctrl-S lists sessions (title, directory, age, state); type to filter, Enter switches (and moves the agent to the new one), the first row starts a new session here. Input history is kept per session in memory and in `<data dir>/term-history/<session>.jsonl`.

## How it is built

- `app.rs`: `App` is the whole state; `handle_key`, `handle_event` (the SDK's events), `handle_msg` and `tick` return `Effect`s (send input, press a button, cancel, switch session, copy, open a link, quit) and `draw` paints a frame. No terminal or network in it.
- `driver.rs`: picks the session at start, runs effects on a worker thread (SDK requests block up to 10 s) and pumps events into the app.
- `runtime.rs`: terminal setup and restore, the loop (poll keys 50 ms, drain events, tick, redraw only when something changed).
- `chat.rs` (view items, cached lines, scrolling, where the images sit and the focused OpenUI target), `forms.rs` (the keys and visual state of OpenUI docs, and the values waiting to be sent), `images.rs` (terminal detection, the probe and encode threads, drawing pictures), `editor.rs`, `history.rs`, `secret.rs` (the masked field), `menu.rs` (commands, switcher), `status.rs`, `sessions.rs` (the sessions sidebar, grouped by repository and worktree), `agents.rs` (the subagents list and a transcript), `widgets/` (side panels), `github/` (the GitHub view: `gh.rs` the read-only runner behind a trait, `model.rs` the JSON, `md.rs` / `doc.rs` / `view.rs` drawing, `format.rs` the block for the model).

## Tests

`cargo test -p suite-term`: unit tests for editing, history, the slash menu, scrolling and follow, prompt buttons, OpenUI forms (focus, typing, debounce, select, buttons, tabs, scrolling to the focus), Esc / Ctrl-C, status lines, session choice, the GitHub view (recorded `gh` JSON through a fake runner, no network), the subagents list, its keys and the transcript, the sidebar's groups and keys, image slots, clipping and the cache, pictures drawn through every protocol into the buffer (png files made on the fly), and screen snapshots at 100x30, 60x20 and others (`tests/snapshots/`, rewritten with `UPDATE_SNAPSHOTS=1`), all on ratatui's `TestBackend`. `tests/daemon.rs` starts the real daemon (echo agent, temp socket and data dir; skipped without bun), connects the app, chats, toggles approvals, `/clear`s, and runs two terminals side by side. Nothing opens a terminal.
